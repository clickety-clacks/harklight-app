# Attention development APNs receiver

This is the existing `AttentionClientDuoPrototype` source lineage under the Harklight product name. The signed physical App ID is `co.clicketyclacks.Harklight` on Team `Z7R59J7QV8`; Apple portal evidence verifies its Push capability. The normal `Scripts/verify.sh` simulator target remains unsigned and uses its existing provisional bundle ID. `Scripts/build-development-receiver.sh` is an explicit physical-device build; it requires the real registered device ID and a verified development profile for this exact App ID. It does not install, launch, export an address, or send a notification.

On a signed physical launch, the app asks APNs to register. Its delegate records `pending`, `registered`, `registration-failed`, `storage-failed`, or `refused` in the app's `harklight.apns.registration.status` preference. A successful nonempty app-issued token is written only inside the app's protected Application Support `APNsSandbox/device-token.hex` file, with first-unlock file protection and mode `0600`. The token is never logged or bundled. Any subsequent handoff to a protected address reference must be separately authenticated to this exact signed installation and performed without displaying token bytes.

The Apple Developer portal verifies the Harklight App ID, Push capability and topic-specific Sandbox key. A protected comparison matched the paired iPad to a registered Team device, but the local Development identity has not yet been matched to the portal certificate row and no Harklight development profile is verified. The old `co.clicketyclacks.Attention` App ID, key and profile are historical setup, not credentials for Harklight. No physical signing, APNs registration, address-reference handoff, or provider send is claimed until the matching profile and signed installation are proven.
